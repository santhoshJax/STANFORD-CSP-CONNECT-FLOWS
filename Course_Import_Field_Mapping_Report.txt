OBJECT 7: CourseOfferingParticipant – Associate
Operation: Create only. Skipped if a record already exists for this
           CourseOffering + Contact, matching on ANY Associate-family
           affiliation ('Associate', 'Course Support Specialist',
           'Guest Speaker') so a re-run doesn't duplicate under a
           renamed value.
===========================================================================

Source / Lookup            SF Field               Notes
-------------------------------------------------------------------------
CourseOffering.Id          CourseOfferingId
Junction file:             ParticipantContactId   Account lookup by
  Associate_ID                                    External_ID_4D__c =
  (matched via Course.RecID)                      "person" + Associate_ID
                                                   Returns PersonContactId (003...)
Speaking_Date               ParticipantAffiliation Derived, NOT hardcoded:
  (junction row)                                    real date            → "Guest Speaker"
                                                     blank / "00/00/0000" → "Course Support Specialist"
Primary_Associate           ParticipantContactId   FALLBACK only — used when the
  (fallback)                                       course has no entry in the
                                                    Associate junction file.
                                                    Numeric value → ID lookup;
                                                    text value → name lookup
                                                    (IsPersonAccount = true).
(fallback rows)             ParticipantAffiliation No Speaking_Date exists on
                                                    fallback rows, so this path
                                                    always resolves to
                                                    "Course Support Specialist".

Skip condition: No associate found (junction file or fallback) and no name match.
               One COP-Associate record created per associate in junction file.

NOTE — Coordinator is NOT a CourseOfferingParticipant record.
Coordinator_ID resolves to a Contact and is written directly onto
CourseOffering.Coordinator__c (see OBJECT 4) — there is no participant
row and no "Coordinator" ParticipantAffiliation value in the current code.
(An earlier version of this flow did create a Coordinator participant
record and used "Aide" for the Associate affiliation; both were replaced
by the logic above.)

OBJECT 9: Course_Department__c (junction)
Operation: Upsert by External_ID_4D__c ("CDEPT-" + row ID). Runs as a
           post-offering task alongside Schedule / COP-Instructor /
           COP-Associate, once CourseOffering has been upserted.
           Source: Course-Department TSV (configured via "Course
           Department File ID"), columns ID, Course_ID, Department_ID,
           IsPrimary. Only IsPrimary=True rows are written (Jul 2 decision).
===========================================================================

Source Column               SF Field                Notes
-------------------------------------------------------------------------
(CourseOffering lookup)     Course_Offering__r      External_ID_4D__c = Course_ID
Department_ID                Child_Department__r    External_ID_4D__c resolved
  (dept lookup)                                      against the actual Account —
                                                      "dept_<id>" or "dept_cat_<id>",
                                                      whichever really exists.
(dept's Parent, if any)     Parent_Department__r    Set only when the resolved
                                                      department Account itself has
                                                      a Parent (i.e. it's a child
                                                      dept). Left unset for
                                                      top-level categories
                                                      (e.g. dept_cat_4) rather than
                                                      self-referencing Parent=Child.
IsPrimary                   IsPrimary__c            parseBool

Skip condition: Department_ID empty/"0", IsPrimary ≠ True, row ID empty
               (no External_ID_4D__c to upsert on), or Department_ID
               doesn't match any Account in Salesforce (logged, not fatal —
               the CourseOffering itself is unaffected).

NOTE: CourseOffering.Department__r (see OBJECT 4) is a separate,
per-offering convenience field derived from the same source file (direct
join on id = Course_ID) — it is NOT populated from this junction object,
and either one succeeding/failing has no effect on the other.


===========================================================================
GLOBAL TRANSFORMATIONS (applied to all records)
===========================================================================

Rule                   Detail
-----------------------------------------------------------------------
Whitespace cleanup     All carriage returns (\r) removed.
                       Leading/trailing spaces trimmed from every field.

Null suppression       Empty or zero values are not sent to Salesforce
                       (field simply omitted from payload).
                       Exception: Tuition_Rule_ID__c defaults to 0.

Person ID prefix       All External_ID_4D__c lookups for persons use
                       "person" + ID  (e.g. "person424").
                       This matches the prefix applied during Student,
                       Instructor and Associate import flows.

PersonContactId        Person lookups return PersonContactId (003...)
                       not the Account Id (001...) — required for
                       PrimaryFacultyId and ParticipantContactId fields.

Date conversion        MM/DD/YYYY or MM/DD/YY →
                       YYYY-MM-DDTHH:mm:ss.000Z
                       "00/00/0000" or "00/00/00" → null

Integer parse          "0" → null (field omitted).
                       Non-numeric → null.

Float parse            "0" or "0.0" → null (field omitted).

Boolean parse          true / 1 / yes → true
                       false / 0 / no → false
                       Anything else → null (field omitted).

Quarter normalisation  Quarter values with year < 13 are remapped to
                       their 2013 equivalent:
                       fa08 → fa13,  wi09 → wi13,  su10 → su13, etc.
                       Applied to AcademicSession and AcademicTerm lookups.

Scientific notation    Closed_DTS values in scientific notation
                       (e.g. 1.23E+10) are converted to integer strings.
